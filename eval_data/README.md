# 初始检索评测集

`retrieval_questions.jsonl` 为 UTF-8 JSONL，每行一题。基于当前两页中文故事 PDF
《哆啦 A 梦与超级赛亚人：时空之战》，用于调试检索评测流程，不代表真实论文检索质量。

## 标注状态

由助手直接阅读完整源文本编写，页码及证据引文已做源文本匹配检查，
**尚未由用户人工复核**，因此这是待复核的开发集，不是独立测试集或人工金标准。
生成标注时没有使用向量检索结果来选择证据、修改问题或筛选成功案例。
用户应对照 PDF 确认问题、答案、引文及无答案判断，再固定版本。

PDF 的路径、SHA-256、数据文件哈希和版本信息记录在
`retrieval_questions.meta.json`。PDF 更新后应重新检查标注，不能直接沿用页码。

## 数据组成

- 20 题：16 道可回答题，4 道无法从文档回答的问题。
- 17 道中文题、3 道英文题；英文题用于检查跨语言检索。
- 可回答题涵盖事实、数值、原因、语义改写、多项信息和跨页比较。
- q006/q007/q008 是同一事实的中英文与改写；q013/q014 为同一事实的中英文表达。
  它们分别共享 `group_id`。可回答题共 13 个事实组，汇总时应同时报告分语言结果
  和组内平均后再按组平均的结果，避免重复问题增加某一事实的权重。
- q016 需要同时检索第 1 页和第 2 页；只命中一页不算完整证据覆盖。

## 字段及判定

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一问题编号 |
| `group_id` | 语义等价或针对同一事实的问题分组 |
| `question` / `language` | 问题与提问语言，证据保持中文原文 |
| `category` | 问题类型 |
| `answerable` | 当前文档是否提供答案 |
| `answer` | 参考答案；无答案题为 `null`，不参与向量检索 |
| `relevant_sources` | 文档 ID、PDF 物理页码（从 1 开始）、该页的 `evidence_quotes` |
| `evidence_policy` | `all` 表示完整覆盖需找到全部引文；`none` 表示无标注正证据 |
| `unanswerable_reason` | 无答案判断理由，仅无答案题提供 |

引文嵌套在对应来源中，避免多页题的页码与证据失去对应关系。
`document_id` 是当前解析器采用的文件 stem，此处为 `paper`；未绑定 chunk ID，
因此更换分块参数后仍可使用同一份标注。

页级 Hit@K 只表示前 K 个片段包含至少一个正确来源页面，不能表示完整回答所需
证据已找齐。页级 Recall@K 应对 `(document_id, page_number)` 去重。
证据覆盖率可按前 K 个片段中完整匹配的引文数 / 全部标注引文数计算；
全部匹配后，才满足这里的 `all` 策略。MRR 可另行按首条证据命中统计。
引文匹配时可先统一 Unicode（NFKC）并去除空白，但不要删除数字或标点。
同一页中出现多条引文时，每条都要分别检查。标注代表一组支持答案的证据，
不是穷尽文档中所有等价表述；匹配失败应人工检查，不宜直接断定检索错误。

`answerable=false` 的 4 题应独立分析，不并入可回答题的 Hit/Recall/MRR 平均值。
当前检索器始终返回 Top-K，尚不能据此评估拒答准确率。

## 使用边界

当前索引只有 4 个 chunks，因此 Top-5 会返回全部语料，Hit@5 和 Recall@5
几乎没有区分度；这份数据应优先看 Top-1 排序、证据覆盖和具体失败案例。
数据量小，且已用于开发，不适合报告为独立、无偏的性能证明。
现已实现批量评测器。使用 `python -m uv run python scripts/evaluate_retrieval.py --offline`
可生成默认 JSON 报告；未为提升这份开发集得分而调整检索参数或修改标注。
每题的 `missing_evidence` 列出各 K 下缺失的引文，`diagnostics.evidence_unavailable_in_index`
列出在整个索引的任意单个块中都无法完整匹配的证据，便于检查切分边界。

若修改标注或替换 PDF，现有元数据中的 SHA-256 将不再匹配，评测会停止。
确认所有相关标注和证据仍然有效后，再更新 `retrieval_questions.meta.json` 的
`dataset_sha256` 以及对应 `sources[].sha256`；不要通过更新哈希来跳过内容复核。
