# 多轮追问人工验收

这些步骤需要真实模型，尚不是已通过的质量评分。先用当前版本完成一项研究，并确认至少一篇论文已成功入库，再从回答下方“继续讨论”输入问题。每次发送都会使用 OpenAI，默认单轮预算 $0.05，追问累计上限 $0.50。

| 场景 | 示例追问 | 核对要点 |
| --- | --- | --- |
| 指代理解 | 刚才提到的这个方法具体怎么工作？ | 指向前文讨论的方法，不无故更换论文；重新取得正文引用 |
| 深入分析 | 它有哪些局限？哪些是作者明确指出的，哪些是你的解释？ | 区分论文事实与分析，不把解释冒充作者结论 |
| 连续追问 | 你刚才说的第二个局限，有什么实验依据？ | 使用上一轮上下文，补检索或读页，引用与结论相符 |
| 多论文对比 | 比较当前两篇论文的方法与实验设置。 | 当前任务确有两篇入库论文时可比较；只有一篇时说明范围 |
| 证据不足 | 这项研究在企业生产环境每月维护成本是多少？ | 缺少依据时诚实说明，不编造金额；保留 insufficiency 标记 |
| 检索后收尾 | 该论文的核心思路是什么？ | 重复检索或读页无新增材料时，进入回答阶段，校验成功即展示回答，不持续循环到无回答停止 |
| 收尾引用错误 | 检查收尾阶段的引文校验失败轨迹。 | 允许修正；默认连续两次失败后停止，不显示未校验的模型草稿，不突破原预算 |
| 范围限制 | 自动下载另一篇最新论文再比较。 | 说明当前仅讨论已入库论文，不出现搜索、下载或入库工具 |
| 刷新和重连 | 发送后刷新页面，或点击重新连接。 | 问题和已核验回答保留；不会重复执行或创建新轮次 |
| 停止 | 发送后点击停止追问。 | 当前步骤完成后停止后续调用，保存已知用量 |
| 重构前的旧任务 | 在已有旧索引的研究任务中重新发送追问。 | 只读复用通过完整性校验的索引；原任务文件不被改写，不能因解析代码路径变化而失败 |
| 预检失败 | 使用缺少可读索引或源文件损坏的任务。 | 显示具体原因；未发出模型请求时不预留整轮费用；未知请求结果仍保守记账 |
| 新建与切换 | 在对话 1 追问后新建对话 2，再切回对话 1。 | 新对话不包含对话 1 的追问历史；切回后消息恢复，论文与研究结果复用 |
| 重置 | 重置当前对话，再发送新问题。 | 当前追问列表和上下文清空；原研究背景、历史审计、费用和任务总轮数保留 |
| 并发与重复点击 | 执行追问时尝试重置；模拟新建响应丢失后重新连接。 | 执行中拒绝修改上下文；重连不自动重复新建或重置 |
| 参考论文列表 | 列出刚刚参考的论文列表。 | 返回上一条核验回答实际引用的论文，包括题名、作者、固定版本链接；不要求正文引文，不把其他候选当作参考文献 |
| 列表范围区分 | 分别列出本对话引用过的论文和全部已入库论文。 | 两种范围分别核对；上轮无引用时诚实说明，不能自动用全部文档替代 |

每轮引用独立编号。上轮的 `[E1]` 不代表本轮已检索到同一证据，需要查看本轮的引文与页码。历史摘要与模型记忆不替代正文证据。

文献列表由 `list_references` 根据保存的文档引用 ID 与已入库论文的登记元数据生成，验证范围不包括论文的研究结论。列表工具不接受模型自写的回答或额外科学断言，生成的元数据列表可直接结束；正文内容回答仍由 `verify_citations` 校验。对话历史现在同时保存核验回答的引用文档 ID，用于准确区分“上一条回答”“当前对话”和“全部已入库文献”。

对照页面与 `data/research_runs/<task-id>/conversation.json`、`conversation/<turn-id>/runner_state.json`、`tool_trace.json` 检查结果。原任务的 `runner_state.json`、`tool_trace.json` 和全文索引应保持原研究内容。

预算耗尽、API 错误、未形成核验回答、语义错误应分别记录，不能仅凭停止状态或逐字引文匹配判定质量通过。自动测试使用模拟模型，覆盖两轮上下文、重新检索、隔离、幂等提交、停止、未知用量与预算保护；不替代本表的真实质量验收。

实现集中在 `research/conversation.py`：`ConversationAgent` 复用执行内核，`ConversationTools` 只开放本地检索、读页和校验。网页通过 `/api/research/jobs/<id>/conversation` 读取/提交，通过 `/conversation/stop` 停止；后台使用包内 `chat` 命令执行已持久化的请求。所有研究和追问共用服务工作锁。

本地对话管理使用 `POST .../conversation/new`、`reset`、`select`。新建与重置带请求标识和上下文版本，重复请求幂等；旧版本页面提交过时问题会被拒绝，避免写入错误的对话。`conversation.json` 保留所有轮次，当前对话按标识及重置代数筛选，预算统计始终覆盖全部轮次。
