# Agent V1 五例人工验收规则

本规则须与输入一起在业务改造前冻结。评分规则、参考材料及人工原文依据不传给模型；模型仅接收案例的研究请求和追问。

## 状态先于分数

- `not_executed`：未提交研究，例如缺少 Key、未启用执行、网络策略不允许或固定材料缺失。不是模型失败，更不是通过。
- `http_rejected`：当前接口拒绝了输入。保留拒绝原因与实际输入，不改预算、问题或材料来掩盖不支持。
- `submission_unknown`：提交结果未确认。不得自动重放；先查看持久化检查点和服务记录。
- `collector_timeout` / `collection_failed`：采集未完成。查看保存的任务标识并确认后台状态，不能把没有采集到结果当作没有付费。
- `executed`：采集到了终止状态。它可能是成功、失败、证据不足或中断；必须查看正文结果并人工评分，不自动代表完成研究。
- 人工结论使用 `not_reviewed`、`pass`、`fail`。记录评审者、时间、理由和逐条关键结论的证据。

## 每例必须核对

1. **任务达成**：是否回答实际研究问题，是否覆盖目标论文及其差异。论文不足时说明实际取得材料，不能为凑数虚构论文。
2. **Agent 行为**：从真实工具轨迹核对候选筛选、读取和后续动作。遇到工具失败或证据缺口时是否合理修正或停止；未实际触发的分支标为未观察。没有必要的补查不应被强行要求。
3. **引用可追溯性**：对每项关键结论核对真实论文、实际版本、对应原文及物理 PDF 页码（从 1 开始）。模型记忆、标题、候选摘要及历史回答不能冒充当前正文证据。
4. **结论支持度**：人工判断引文能否支持该项结论，是否混淆实验条件、以相关性代替因果性或夸大论文结论。文本匹配通过不替代此项。
5. **执行边界**：检查停止原因、步骤和工具限制、用量、时长与追问范围；失败保留原因，未知调用不自动重放。先记录当前基线实际限制，不要求它假装已实现 V1 目标。

满足案例全部适用预期、关键结论均有合适依据且无下述硬性失败才可判为 `pass`。证据不足案例可以通过：须准确说明已取得的材料范围及缺口，不能把有限检索解释成全文绝对不存在某数据。

## 硬性失败

- 虚构论文、版本、引用或页码。
- 用不相关原文支持关键结论，或用其他论文的证据替代声称的来源。
- 将训练、标注或推理成本冒充企业每月维护成本。
- 缺少证据仍输出看似完整的事实，或无依据地宣称穷尽材料。

任一硬性失败使该例为 `fail`，即使请求成功、文字流畅或引用文本核验通过。

## 留下可复核记录

在每例 JSON 的 `review` 中填写评审者、评审时间、结论及 `failure_reasons`；`claims` 逐条记录回答中的关键结论、论文版本、原文短引文、物理页码、支持/部分支持/不支持及理由。连续追问逐轮核查。缺少 PDF 或页级依据时保留 `not_reviewed`。

五例全部有实际结果和人工判定后，才汇总是否达到至少 4/5；未执行或未评审不能变成通过。不报告小样本“普遍准确率”，不将单次前后差异当作统计显著提升。

## 比较条件

基线与改进版使用相同冻结案例、论文版本、模型及可用生成设置。当前基线研究预算 $0.10，追问每轮 $0.05；正式 V1 的上限更高，但对比运行仍使用冻结请求。额外测试目标上限时另存记录，不混入同条件结果。

在线模式检验实际 arXiv 搜索与下载；固定材料模式使用已校验材料但仍调用真实模型。候选和正文缓存命中均需从真实来源记录标注，缓存命中不证明在线链路通过。`controlled_web_test` 是工具链回归证据，不能计入真实模型效果分数。
