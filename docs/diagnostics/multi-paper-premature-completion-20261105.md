## 可重复失败与根因

先建立 `tests/web/test_research_coverage.py`，再检查生产实现。原始两个场景分别为第二篇已选但未获取、第二篇已入库但未读。失败循环重复两次，约两秒均为 `2 failed`。

扩展为三条结束路径后，修复前：

```powershell
python -m pytest tests/web/test_research_coverage.py -q --tb=line --basetemp tmp/checks/coverage-red-004 -p no:cacheprovider
# 6 failed in 14.96s
```

症状包括：`insufficient_evidence` 直接终止，或 `sufficient_evidence` 通过但回答只含一篇论文的引用。另一个重要对照是最小复现中尚有充足预算、没有无进展计数，仍可出现提前结束，因此预算并非唯一根因。

确认的原因：

- 原收尾检查主要识别“是否存在已校验回答”，不检查明确选中的相关论文是否仍有可执行的获取/入库/读取待办。
- 原证据复查以全局搜索次数、是否读过任一页面为准；读过第一篇就可能跳过复查，而且建议读取的仍是第一条已有证据。
- 无进展保护针对反复检索第一篇强制回答，缺少一次转向尚未检查的已选论文的机会。
- 模型压缩上下文保留候选状态，但没有明确、紧凑的逐篇证据覆盖及下一步提示。

## 修复

1. `research/coverage.py` 从真实候选、选择、工具观察和正文证据构建逐篇覆盖信息。只处理显式选择的论文，不使用目标篇数判定质量。
2. 模型上下文的 `completion.selected_paper_coverage` 保留覆盖与下一步；最小投影也不丢失。它只表示获取/阅读覆盖，不表示结论支持度。
3. 在主动结束、回答校验前，以及无进展交接处，最多提供一次 `selected_paper_needs_review` 反馈。建议指向缺失论文的获取、入库或定向检索。
4. 纠偏前保守检查完成后续获取、入库、读取和回答所需的剩余步数、工具次数、费用和 token；保留报告预留。每次真实请求仍须通过原有实时预算、截止时间、重复调用及取消检查。
5. 明确获取/入库失败、已尝试的空检索、未选论文、硬预算回答阶段均不会强制继续。纠偏标记随现有 decisions 持久化；恢复不重置标记、用量或预算。
6. 保留字面引用校验，不把历史回答当正文，也不增加语义真实性保证。

上下文回归还发现覆盖提示会挤占十候选场景的输入空间。因此空覆盖不写入提示，移除冗余说明，并在原压缩策略末尾增加 400 字符的字面片段投影；原始证据不裁剪，输入上限不增加。扩展现有真实字节估算器测试，覆盖 5/10 候选、已入库/未入库及选择 1/3 篇的组合：先出现 `2 failed, 6 passed`，修复后 `8 passed`，完整保留逐篇待办和正文证据。

无进展属于启发式保护，预算/时间/工具硬上限仍优先。若完整搜集上下文无法估算或容纳，保留受限回答上下文的退出路径。一次纠偏被忽略后不会无限强迫模型继续。
